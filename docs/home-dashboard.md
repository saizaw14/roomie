# Home dashboard

Design reference: the published Figma Make site at https://frown-naming-66108554.figma.site, its publicly served CSS/source bundle, and the user-supplied source ZIP's `Home`, `Header`, and `BottomNav`. Layout uses the source's 430px mobile canvas, Inter typography, household switcher, teal gradient balance card, rounded content cards, bottom navigation, and floating Add Expense action.

The prototype's fictional balances, payments, bills, and activity are replaced with actual available data. The card shows an **expense-only** balance: posted expense payments minus posted participant shares for the current account's membership. Voids are excluded. Loading, missing migration, missing membership, and invalid financial reads do not show a fabricated zero. Zero appears only after a successful expense read. This is a read model; it creates no mutable balance table. Confirmed repayments and settlement suggestions remain future work.

Recent activity comes from the existing RLS-protected `activity_events`, restricted to the selected household's expense events. Initially three events are shown; View more shows up to 50. Each links to its expense and complete revision history. Save/edit/void mutations invalidate expense and activity queries. Query keys include the authenticated user and household; existing auth cache clearing remains in force.

Household switching, invitations, creation/joining, members/settings, expenses, profile, refresh, and logout stay accessible. Settle up, Bills, and the notification icon show clear availability information because repayment, recurring bill, and notification flows do not exist yet. They never create records or open a fake payment flow. Notice actions scroll to the visible information panel. Upcoming bills have an explicit unavailable state, not fictitious due dates. No demo-data labels are added to the real dashboard.

No new migration or dependencies are needed. Existing profiles, households, and expenses migrations are required. Pure summary tests cover credits/debts, voids, edits, account membership selection, empty data, and invalid amounts. Browser/native visual and hosted end-to-end verification remain pending because computer-use permission was unavailable in this session. Device checks should cover narrow screens, text scaling, short viewports, bottom safe areas, household/account switching, offline loading errors, activity refresh after financial edits, and notice visibility.
